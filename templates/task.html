        How sending works
    
        Send continues the same Codex thread (its history stays inside Codex, so the prompt cache is reused); while a turn is running
    it is added to that turn. Model, reasoning, speed, sandbox, approval and web search are fixed for the task: changing them mid-thread lowers cache reuse.
    “Retry with …” changes the reasoning effort only when you click it.
        
    
        Schedule Instruction sends the text to this same Codex thread later: once every selected task has completed and this thread is idle
    (one instruction at a time per thread, oldest first). Its speed is the one you pick here, whatever the last turn used. Reasoning effort and approval come from the task.
    If Codex stops unexpectedly during that turn, the task's automatic recovery continues the thread; the instruction is never sent twice.
